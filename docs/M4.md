# M4 — Perception transport

Getting frames to models, and their answers back to a human, without letting the
slowest model set the pace for everything else.

## The problem, stated properly

Tiers differ by three orders of magnitude. Foveate measured, on this class of
hardware:

| Tier | Runtime | Latency |
|---|---|---|
| Fast (detector) | ONNX Runtime / CoreML | **8.2 ms** |
| Fast (detector) | Ultralytics / MPS | 10.8 ms |
| Scene (VLM) | qwen2.5vl:7b via Ollama | **8.5 s** |

A design where a 8.5 s consumer can stall an 8 ms one is not a tiered system, it
is a slow system with extra parts. Two properties follow, and everything here
exists to serve them:

1. **No consumer may gate another.** Not the camera, not the control loop, and
   not each other.
2. **Every observation must carry when it was true.** A narration displayed
   beside live video is read as a statement about *now*. At 8.5 s and half a
   room away, that is false, and the operator has no way to know unless we say.

## Why not the bus

Foveate carries pixels as JPEG → disk → path-on-Redis → worker reads from disk.
That is a sound answer to *its* problem: several Python processes on one host
needing to share pixel data.

It is the wrong answer to ours, for reasons that are about our shape rather than
its quality:

- The frames are **already encoded**, once, for the browser stream. A bus route
  pays the 23.6 ms encode a second time and adds a disk round trip.
- `FrameHub` **already provides the property the bus was chosen for**: the
  encoder never waits on a consumer, and each consumer independently takes the
  newest frame, dropping what it missed. That is catch-up sampling, in memory,
  with no broker.
- It would add Docker and Redis as prerequisites for perception on a robot that
  otherwise needs neither.

**What we would give up by not using it:** replay, durability, and consumer
groups. We do not need them yet. When we want to re-run a model over yesterday's
drive, a broker earns its place — and by then the observation schema below is
what we would replay.

## Two access patterns, matched to cadence

The one thing a naive "just read the stream" design gets wrong is slow
consumers. MJPEG *pushes*: a tier that thinks for 8.5 s finds 8 seconds of
frames buffered in the socket and reasons about a scene the robot has left.
Push transport quietly reintroduces the coupling we are trying to remove.

| Endpoint | Shape | For |
|---|---|---|
| `GET /stream` | multipart MJPEG, pushed | tiers that keep up — a detector at ~10 ms |
| `GET /frame.jpg` | one request, one frame, newest | tiers that do not — anything measured in seconds |

Pulling makes staleness structurally impossible: you ask when you are ready, and
you get what is true now. Adding a third tier at a fourth cadence costs nothing
and coordinates with nobody.

`/frame.jpg` carries identity in headers so a consumer can attribute its result
without decoding the image:

```
X-Frame-Seq                89
X-Frame-Captured-Unix-Ms   1788626449311
X-Frame-Age-Ms             85.2
X-Frame-Width / -Height    1280 / 720
```

## Results come back dated

`POST /perception` takes one tier's output. Newest per tier replaces older;
nothing queues, because a console wants the current belief, not a history.

```jsonc
{
  "tier": "scene",            // "fast", "scene", …  — tiers never overwrite each other
  "model": "qwen2.5vl:7b",
  "frameSeq": 89,             // which frame this describes
  "capturedAt": "…",          // when that frame was taken, not when we answered
  "latencyMs": 8500,          // how long the model took
  "width": 1280, "height": 720,
  "detections": [{"label": "chair", "confidence": 0.91, "box": [x1,y1,x2,y2]}],
  "text": "a corridor with a chair on the left",
  "hazards": ["cable across the floor"]
}
```

The console computes two ages from this and shows both:

- **`ageMs`** — how old the *frame* is. This is the honest one, and it is
  rendered as a prefix on every narration: `[9.1 s ago] a corridor with…`
- **`staleMs`** — how long since the tier reported at all, which distinguishes
  *slow* from *dead*.

Detections are drawn over the live video, dimmed as they age and drawn red past
600 ms. A confident green box on a moving robot, describing a frame from a
second ago, is worse than no box.

## Next: the tiers themselves

Native arm64, out of process — the control loop is a 20 Hz safety-critical path
and must never share a runtime with inference. Rosetta reinforces this (the
bridge pins `s1teleop` to amd64, while CoreML wants native arm64) but the
safety argument stands alone.

Model choices are already measured, so we do not re-derive them:

- **Fast tier: yolo11s**, ONNX Runtime with the CoreML execution provider —
  8.2 ms, and the same ONNX artifact runs TensorRT on a Jetson later.
- **Scene tier: qwen2.5vl:7b**, not moondream. Foveate measured moondream at
  2.0 s but **0/3** on schema-compliant output, with an invented second person.
  qwen2.5vl:7b was 3/3. Moondream is a reasonable choice only if we want prose
  for a human to read and nothing downstream depends on the structure.
